# unirank — 跨基准通用记忆检索排序库

**设计宪法**（2026-09-19 双基准战役的全部教训，一条不省）：

1. **零绝对数值** — 特征进入排序器前一律池内分位化（`core.ordinal.pool_rank`）。
   树的分裂边界只能是序数规则（"池内相对更长的排前面"），分布无关，跨库直迁。
   实测：LoCoMo训→LME零标注 79.2@5 / 92.8@15。

2. **信号带验证注记** — 每个信号标注其适用形态：
   - `[双库]` 两基准都活（双cos/长度/G1/排序学习）
   - `[粒度]` 只在指定粒度活（寒暄效应=原子句；三团=聚合层）
   - `[形态]` 只在指定聚合形式活（G1=会话max；问号=句型分离器而非判别器）
   判死一个信号前，必须穷举聚合形式 + 双空间（词面/向量）验尸。

3. **三级聚合** — 原子句 → 记录 → 会话，每级的信号形态不同（`aggregate.py`）。

4. **双通道** — 1024(BGE) + 256(qwen) cos 通道并集做池；排序层256倾向主导（两库验证）。

5. **部署三模式**：
   - 零标注直迁（预训练ranker + 冻结配置，任何新库开箱即用）
   - 反馈在线爬升（用户反应做弱标注，冷启动71 → 运行中变强）
   - 少量标定（~500题本地训练，上界模式）

6. **验收纪律**（bench/）— 分折单位=数据生成单位；增益必须同条件双基线；
   结论前先归因消融；欢庆前先问增益的成分。

7. **零硬编码原则** — 所有数值从数据计算得出(质心/分位/密度/DF截断)。
   词表、标点规则、绝对阈值不得进入运行时(词表只存在于bench的离线发现工具)。
   问句方向=问题集质心(自监督, AUC 0.968); 停用词=语料DF自动derive;
   句长窗=分布分位; 寒暄=kNN密度×长度分位。
   记忆库没有任何形式的"答案"——它只是排序。
